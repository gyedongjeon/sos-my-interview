## Request

Turn the initial mock interview prototype into something usable for real interview practice:

- Score each answer in two separate parts, English and content, including pronunciation,
  intonation, and stress, and read questions aloud with a better local voice.
- Keep a dated history with scores and a low-quality recording, so progress can be tracked.
- Take a résumé and job postings (link or text) and write interview questions for each company,
  with a per-posting résumé and cover letter.
- Let the user choose the language of the feedback.
- Package the backend and frontend as one desktop app, and have the user enter their own model
  and API key in the app instead of a `.env` file, so someone else can use it too.
- Rename the project to `sos-my-interview` after the repository rename, and give the app a look
  that fits the name.
- Move the feedback language choice from the navigation bar to Settings, and have it chosen on
  the first launch.
- Release the project under the MIT License, and credit the font and other third-party work,
  inside the app as well.
- Write down Semantic Versioning as the versioning rule.
- Fix the interviewer's voice being silent in the browser, and hide the question text until
  asked for, so that listening is practised too.

## Changes

- **Feedback, history, job postings**: answers are transcribed locally with Whisper and scored by
  an LLM (through LiteLLM) on English and content; the audio is scored for pronunciation,
  intonation, and stress when the model accepts audio. Questions are read aloud with a local
  Kokoro voice. Attempts are saved with transcripts, scores, feedback, and a low-bitrate
  recording, and listed by date with the change against the previous attempt. A résumé and job
  postings can be added; posting text is extracted from a link (schema.org `JobPosting` data
  first, then the page's main text). Each posting has its own page, questions generated at a
  chosen difficulty, and an optional résumé and cover letter of its own.
- **Feedback language**: stored in the database, starting from the browser's language. It was
  first a picker in the navigation bar and then moved to its own card at the top of the Settings
  page, above the model, so it is seen on the first launch. Translating the whole UI was
  considered and left out: the questions and answers are in English anyway, and the feedback,
  where understanding matters, already follows this setting.
- **Settings page**: provider, model, and API key are entered in the app, saved in the local
  database, and checked with a test request. The key is never sent back to the page. The app
  opens on this page when no model is configured.
- **Desktop app**: a thin Electron shell in `desktop/` starts the backend on a free port and
  shows it in a window; the backend now also serves the built frontend. The Python side is run
  with `uv` rather than frozen into a binary, which keeps the native dependencies (Whisper,
  ONNX Runtime) out of a fragile packaging step at the cost of requiring `uv` on the machine.
  The packaged app keeps its data in the user's application-support folder. Electron has no
  speech service behind the Web Speech API, so live captions there come from the local Whisper
  model, cut at pauses. Merging `desktop/` into `frontend/` was tried and reverted: the web UI
  also runs on its own in a browser, so the shell stays a separate package.
- **`.env` removed**: with the Settings page in place, `.env` loading, `.env.example`, and the
  `python-dotenv` dependency were dropped. Optional tuning values (`WHISPER_MODEL`, `TTS_VOICE`)
  are plain environment variables.
- **Rename and look**: the project, packages, app name, and the internal environment variables
  (`SOS_MY_INTERVIEW_*`) follow the new repository name, so the packaged app now keeps its data
  under `SOS My Interview` in the application-support folder. The UI uses two custom daisyUI
  themes built on a rescue-signal idea: signal orange on warm paper by day and on navy at night,
  a life-ring logo and favicon, "SOS" in Morse code as the brand motif and page loading
  indicator, and a bundled display font (Bricolage Grotesque) for headings. Two other directions
  were proposed and not chosen: an emergency-room "vital signs" look and a lighthouse look.
- **License**: the project is released under the MIT License (`LICENSE`). The libraries and the
  font bundled into the built app are credited, with their license texts, in
  `frontend/public/THIRD_PARTY_NOTICES.txt`, which ships with the app; the Settings page lists them
  with a link to the full texts.
- **Versioning**: `docs/git-workflow/versioning.md` sets Semantic Versioning as the rule: how
  commit types map to version numbers, the 0.x rules, one shared version across the three
  packages, and `v`-prefixed release tags.
- **Voice on first use**: the Kokoro model files used to be downloaded inside the first speech
  request, which left the first question silent for minutes. They are now downloaded in the
  background, and the browser voice reads questions until the download is done.
- **Listening first**: on the interview page the question text is hidden until "Show question"
  is pressed, for the main question and each follow-up.

## Verification

- Backend endpoints were exercised with real requests: transcription of synthesized speech,
  voice synthesis, scored feedback and speaking feedback, tailored questions from a PDF résumé
  and a cover letter, text extraction from a JavaScript-rendered job board link, attempt storage
  and recording playback, and saving, testing, and removing the model settings (valid and
  invalid keys).
- `npm run build` (type check and build) passes in `frontend/`; `tsc` passes in `desktop/`.
- The desktop app was launched in development mode and as a packaged build: the page loads, the
  camera and microphone open, voice synthesis works after downloading its model, a first launch
  with no model lands on the Settings page, and quitting stops the backend process.
- Whisper live captions were checked inside the desktop window by feeding synthesized speech
  through the caption code.
- After the rename and restyle, `npm run build` passes in `frontend/` and `uv lock --check`
  passes in `backend/`. `tsc` was not rerun in `desktop/` (its dependencies were not installed),
  and the desktop app was not launched again, so the renamed environment variables and the new
  start screen are unverified there.
- The new look was checked on screenshots of the home, common questions, history, and settings
  pages in light mode and the home page in dark mode, and by hand in a browser against the
  development servers. The Settings screenshot shows the language card above the model card and
  the open source list.
- Voice on first use: a server started on an empty data folder answered `/api/speech` with an
  immediate 502 and began the download in the background; a server with the model files
  returned WAV audio. The switch to the browser voice after that 502 was not checked in a
  browser. Hearing the question with the downloaded model was confirmed by hand.
- The "Show question" button was type-checked and built, not clicked through.
- Not verified: a full recorded answer with a real voice inside the desktop app, providers other
  than Gemini with a real key, and the packaged app on another machine (the build is unsigned).
- The intermediate commits were checked with a type check and a backend import, not run.
